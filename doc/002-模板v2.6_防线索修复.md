## 1. 需求背景（用户原话）

> 「请软件架构师帮优化现有项目模板，先理解，提出立体理由，评估好处和债务，**划算再优化**。」
> 追问执行范围时选择：「P0+P1+P2 全做（推荐）」。

用户没有指定改哪些文件，而是把「划不划算」的裁决权交了出来。因此本版的正确做法是：
**先复现证据，再按 收益÷成本 分级，只做划算的，其余记账。**

## 2. 验证结果（改前数据对比/报错现场）

审前实测基线：`bash tools/selftest.sh` 31 项断言全绿；`bash tools/run.sh` 七门全绿；
入口文件 9.9 KB / 24 KB（41%）。**模板本身是健康的**，本版修的是它自己的防线。

D1/D12 属「沉默的失败」（闸门 PASS 却错，最危险）；D2/D3/D4 属「出声但误导/崩溃」。

## 3. 设计方案（逻辑+口径依据，引用证据文件）

**分类轴**：防线失效 = ①出声的失败（可控）②沉默的失败（危险）③覆盖盲区。

| 组 | 处置 | 依据 |
|---|---|---|
| P0 | D1、D2+D3、D4 | 消除唯一一处沉默失败 + 两处误导/崩溃。成本 ≤15 行，不动任何对外接口 |
| P1 | D6、D5 | 切断「新项目继承模板自述文档」；口径外文本显式报出 |
| P2 | D7、D8、D9、D10、D11、D12 | 纯文档/注释/断言加固，零功能风险 |
| P3/P4 | `align_report.py` 拆模块、`align.sh --out` 改名 | **不做**：前者回归风险高且已稳定工作；后者破坏兼容性。按 R6 减法设计，记账优于修复 |

**一处改动了原判断（须留痕）**：原方案 P1 打算把 `README.md` 纳入门7 口径。
执行时推翻——`README.md` 12.5 KB 纳入后，模板本体将达 23.5/24 KB（98%）。
若为此调高预算值，就是**给门量体裁衣**，闸门即失去意义。
故改为：**口径不动，只把口径外的根目录文本显式报出**（不再隐形），
并把 README 膨胀升级为显式债务（见本节「已知问题」与 STATE.md）。
由此新增 C06 把「不得为让某个文件过关而扩张口径或调高预算值」固化为硬约束。

## 6. 反转记录（反转了哪条旧决策，为什么；无则写「无」）

**反转 1（本版方案内部反转）**：原计划把 `README.md` 纳入门7 口径 → 改为**不动口径、只显式报出**。
原因：纳入后模板本体 23.5/24 KB（98%），为让其通过而调高预算 = 给门量体裁衣。
反转产物 = 新增 C06 硬约束 + 把 README 膨胀升级为 STATE.md 已知问题（转入下一版）。

**反转 2（防线判据反转）**：旧版只关心「门是否 FAIL」，不关心**失败方向**。
本版确立新判据：**漏报（假 PASS）比误报危险**，误报只是吵人，漏报是替错误背书。
该判据同时适用于 D1（`__MACOSX` 假 PASS）与 D12（注入变 no-op 使断言静默失效）——二者同族。

**未反转**：C01 / C02 保持有效，未被本版任何改动推翻。
