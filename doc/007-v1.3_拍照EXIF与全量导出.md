## 1. 需求背景（用户原话）

> app 里面的相片拍摄 参考 /Users/sux/Desktop/hqz-supervision ，修改 模板，添加参考，图片压缩参考 supervision ，在上传模板中添加参数sheet ，是否显示轨迹也 也在参数折磨，默认不显示，添加下载 ,所有样地再一个excel中下载，分为多个 sheet

三问三答（2026-11-23）：

1. 拍照：**对齐 supervision 全链路**（水印版式 + 压缩参数 + 真 EXIF 保留）。
2. 轨迹：**只改「功能」默认值**为「拍照」，想开轨迹就在 value 里加「轨迹」；不删轨迹功能。
3. 导出：**每个小班一张 sheet**，所有小班放在一个 xlsx 里下载。

## 2. 验证结果（改前数据对比/报错现场）

| 项 | 改前 |
|---|---|
| 拍照水印 | 底部黑色渐变条 + 白字，字号 = 画宽/48；时间取 `new Date()`，坐标只取浏览器定位 |
| EXIF | 压缩后**全部丢失**（Canvas 像素重绘的必然结果），服务器那份照片没有时间/坐标元数据 |
| 参数默认 | 「功能」默认 `拍照;轨迹` → 没写参数表的老 Excel 都会显示轨迹卡片 |
| 导出 | 只有 `/admin/api/projects/<id>/source`（下载原始 Excel），**调查数据无法导出** |
| 模板 | 仓库里只有原始总表，没有带「程序参数」sheet 的参考模板 |

## 3. 设计方案（逻辑+口径依据，引用证据文件）

- **EXIF 两条**（照抄 supervision `doc/017`）：
  ① 水印的时间/经纬度**优先取原片 EXIF**（相机定位比浏览器 geolocation 权威、不依赖权限）；
  ② 压缩后把原片 EXIF **回写**进上传的那份，清理三类必坏标签：`Orientation` 归一为 1、删尺寸标签、删 `MakerNote`。
  任何 EXIF 失败都静默退回原行为，绝不因为它丢照片。
- **水印版式**：半透明白底块（alpha .62）+ 实心黑字，圆角，左下角；字号 = 画宽/34（下限 18），底块超过画面 55% 时整体缩字号。理由是省比特（描边是高频边缘，JPEG 更费字节）。
- **轨迹默认关**：`param_parser.KEYS["功能"]` 默认值改「拍照」；`has_track` 仍由「功能」里是否含「轨迹」决定，不新增第二个开关（双开关会出现「功能含轨迹但显示轨迹=否」的矛盾态）。
- **导出切法**：外业交回是「一张小班一张表」的签字习惯，按小班分 sheet 可直接打印归档；口径复用 `calculations`，导出不另算一套。
- **模板**：`data/程序参数模板.xlsx` 只放 6 列参考行（key|value|类型|默认值|说明|示例），业务员把它复制进自己的总表即可。

## 6. 反转记录（反转了哪条旧决策，为什么；无则写「无」）

- 反转 C15「无参数表时行为必须等于 v1.0 默认值（拍照+轨迹）」→ **C17**：默认只拍照。原因：轨迹是耗电且多数小班不需要的可选项，默认关更贴合外业；需要时参数表一行即可打开。
- 反转 v1.0「水印用黑色渐变条 + 白字」→ supervision 的白底黑字块。原因：渐变条在同质量下体积更大、小字容易糊。
