# 008 - v1.3.1 轨迹关闭（不显示）与「轨迹采样间隔」容错

## 1. 需求背景（用户原话）

> `/Users/sux/Desktop/hqz-exp-survey/tpl/中幼林抚育林木采伐调查设计总表.xlsx` 轨迹不显示，修改 程序参数 让轨迹不显示

三问一答（2026-11-23）：轨迹卡片要**隐藏**（保持 v1.3 口径：功能只保留「拍照」）；顺带把该总表传不上去的问题一起修掉。

## 2. 验证结果（改前现场）

| 项 | 改前 |
|---|---|
| 该总表的「程序参数」sheet | `功能 = 拍照`（已经不含轨迹），但 `轨迹采样间隔 = 0`、默认值列也写 0 |
| 解析结果 | **整份工作簿报错被拒**：`程序参数第7行 key「轨迹采样间隔」：0.0 超出范围 1-60`；连 684 条小班都进不了库 |
| 参数表自己的说明 | 写着「不开轨迹时该项不生效」——**实现却在无条件校验**，说明与代码不一致 |
| 详情页轨迹卡 | `templates/index.html` 里没有初始 `hidden`，靠 JS 应用参数后才隐藏，慢网/脚本报错时会闪一下 |

结论：用户的「让轨迹不显示」在数据上已经满足（功能无「轨迹」），真正卡住的是**参数校验把「不开的开关」也当成了坏数据**。

## 3. 设计方案（口径依据）

- **一个开关不变**（C17）：显不显示轨迹仍只看「功能」里有没有「轨迹」，不引入第二个布尔键。
- **不生效的项不校验**：「轨迹采样间隔」只在 `轨迹 ∈ 功能` 时才校验 1-60；不开轨迹时该行**整行忽略、回落默认 5**。理由是表内说明就是这么写的，且历史 Excel 用 0 表示「不要轨迹」是自然写法，让它拖垮整份上传属于误伤。
- **开了轨迹仍然严格**：`功能 = 拍照;轨迹` 且间隔写 0 时照旧报 `超出范围`——错误在最该暴露的时刻暴露，不会被静默吃掉。
- **前端双保险**：`#trackCard` 在 HTML 里默认带 `hidden`，命中参数后才由 `applyParamsToDetail()` 移除，避免首屏闪现一个「卫星轨迹」卡片。
- **数据同步**：把该总表的 `轨迹采样间隔` 与默认值列从 0 改成 5，让表自身合法（不开轨迹时该值不生效，仅为将来打开轨迹时不挖坑）。

## 4. 代码修改（文件+要点）

| 文件 | 要点 |
|---|---|
| `param_parser.py` | `parse_program_params` 改成两遍：先落地「功能」→ 求 `track_on` → 再逐行校验；`轨迹采样间隔` 在 `not track_on` 时 `continue`（回落默认 5）。列表型 key 的校验抽成 `_list_items()`，行为与报错文案不变 |
| `templates/index.html` | `#trackCard` 加初始 `hidden`，未开轨迹时不会被 JS 之前的一瞬渲染出来 |
| `tpl/中幼林抚育林木采伐调查设计总表.xlsx` | 程序参数 sheet：`B7 轨迹采样间隔 0 → 5`、`D7 默认值 0 → 5`（其余 6 列内容不动，data/样地表 684 条不变） |
| `tests/test_app.py` | 新增 2 条断言（见下），导入 `public_params` |
| `app.py` | `ASSET_VERSION` → `v1.3.1`（HTML 内的静态资源引用随之更新） |
