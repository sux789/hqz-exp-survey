# 009 - v1.4 一个小班多块样地、样地号切换、按样地导出

## 1. 需求背景（用户原话）

> 部署 样地号默认 1 ，一个小班号对应多个样地号，可以新增样地，点调查，多个样地号切换，当前样地号显示为激活颜色，非当前样地为灰色，或者在小班列表里面可以点击样地号，理解扩展我的意思，便于操作不容易出错，下载每个小班样地一个sheet,sheet 名称 按已经填写的小班样地号排序

拆成 5 条可验收的：

1. 样地号默认 `1`，上传即有，不用先点新增；
2. 一个小班可加多块样地，[＋ 新增样地] 自动递增号；
3. 详情页能切样地：当前号实心绿、其余灰色；
4. 小班列表里样地号可直接点进对应样地，列表能看出「已调查几块」；
5. 导出每块样地一张 sheet，sheet 名按已填的小班号→样地号排序。

## 2. 改前现场（为什么必须动数据模型）

| 项 | 改前 v1.3.1 |
|---|---|
| 调查数据 | `subcompartments.survey_json` 一行一份，结构 `{plot_no, trees, cut}` |
| 轨迹 / 照片 | 同样挂在小班行 / `photos.subcompartment_id` |
| 多块样地 | **做不到**：填第二块只能覆盖第一块；列表也没有「样地号」这一列 |
| 导出 | 每个小班一张 sheet，sheet 名 `XP-01`，第二块样地无处可放 |
| 样地号 | 只是 survey 里的一个字符串，改号等于改调查数据，容易和被覆盖的数据一起丢 |

## 3. 设计方案（口径依据）

- **样地独立成表** `plots(id, subcompartment_id, plot_no, survey_json, track_json, created_at)`，`UNIQUE(subcompartment_id, plot_no)`。
  调查、轨迹、照片（`photos.plot_id`）都挂样地；小班行只留基础数据。理由：样地是外业的最小记录单元，照片与轨迹天然属于「这一块地」。
- **默认样地 1**：`insert_project` 每个小班都建一块「样地 1」；老库由 `ensure_plots()` 幂等迁移——把原 `survey_json`/`track_json` 搬进样地（号沿用原来填的 `plot_no`），老照片 `plot_id` 回填。
- **样地号唯一且必填**：新增默认「已有纯数字号最大值 + 1」，改号 / 新增撞号 → 400；空号 / 超 20 字 / 控制字符 → 400。
- **至少留一块**：删除最后一块样地被拒（一个小班不能没有样地，否则列表页无处可点）。
- **只有一个「当前样地」**：切换前先把调查与轨迹落盘（`switchPlot` 里 `saveSurvey` + `stopTracking(true)`），再换数据，避免串数——这是「不容易出错」的关键。
- **导出切法**（C18 → C19）：每块样地一张 sheet，sheet 名 `小班号-样地号`（`XP-01-2`），顺序用自然序（`XP-2` 在 `XP-10` 前、样地 2 在样地 10 前），重名才加 `(2)`。
- **旧接口不拆**：`PUT /api/subcompartments/<id>/survey|track|photos`、`track.gpx` 一律落到第一块样地，v1.3 的缓存页面不会突然 404。

## 6. 反转记录

- 反转 C18「每个小班一张 sheet」→ **C19**：每块样地一张 sheet，名 `小班号-样地号`。原因：一个小班能有多块样地，挤在一张 sheet 无法签字归档。
- `survey.plot_no` 退休：样地号移到 `plots.plot_no` 作为唯一事实源，避免「调查数据里写着 2、样地表里是 1」的双真相。
