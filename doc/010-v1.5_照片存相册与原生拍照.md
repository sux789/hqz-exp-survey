# 010 - v1.5 迭代记录_照片存相册与原生拍照

## 1. 需求背景（用户原话）

> 拍照参考 /Users/sux/Desktop/hqz-supervision‌ 存储在相册 app名称/小班号 文件名 水印 app 小班号 样地号，写在参数里面，参数有项目名称，有说明，修改程序参数sheet，不再有从相册选择图片

追加确认（三问三答）：

1. 照片最终保存到哪里 → **先只存储手机相册**，注意压缩、压缩后的 meta 信息参考 supervision；
2. 相册目录/文件名里的「app 名称」取哪个值 → **项目名称**，没有项目名称就默认 App 名称；
3. 「不再有从相册选择图片」怎么实现 → **原生相机插件**。

## 2. 验证结果（改前现场）

- `templates/index.html` 拍照按钮文案是「拍摄 / 选择照片」，`input[type=file][capture]` 在部分机型仍会弹出「相机 / 相册」二选；
- `static/app.js` 拍照链路末端是 `POST /api/subcompartments/{id}/plots/{pid}/photos`（上传服务器），相册里没有任何副本；
- 参数表只有 6 个 key，水印内容只有「时间 / 坐标 / 小班」，**样地号在 plot_no=1 时被隐藏**，文件名由服务端 `小班号_样地N_时间戳` 拼死；
- `android/` 壳只有 `MainActivity extends BridgeActivity {}`，没有任何原生能力，无法在断网/后台时把照片稳定落到相册。

## 3. 设计方案（逻辑 + 口径依据）

参照 hqz-supervision 的拍照口径（`static/app.js` 的 `handlePhoto`、`android/.../AppPermissionsPlugin.java` 的 `savePhoto`）：

1. **参数表**新增四个 key（`param_parser.py`，C15 同一套校验风格）：
   - `项目名称`（文本，不能含 `/` `\` `..`）——相册顶层目录、水印首行、文件名共用；留空由 App 端回落 App 名「抚育调查」。
   - `说明`（文本）——水印里的一行说明，填了才占行。
   - `目录`（模板，默认 `{{项目名称}}/{{小班号}}`）——相册子目录 `Pictures/{目录}/`。
   - `相片文件名`（模板，默认 `{{项目名称}}_{{小班号}}_样地{{样地号}}_{{时间}}`）——不含扩展名。
2. **模板占位符固定五个**：`{{项目名称}} {{说明}} {{小班号}} {{样地号}} {{时间}}`（`时间=YYYYMMDD_HHMMSS`）。未知占位符 → 带 Excel 行号报错，理由同 supervision `param_parser`：写错的占位符静默变空，照片只剩时间戳，事后无法按小班追溯。
3. **水印内容**由 `时间;坐标;小班` 扩为 `项目名称;小班;时间;坐标`；「小班」一行**恒定带出样地号**（`小班：XP-01  样地：2`），一个主伐小班常布 2–5 块样地（C19），只写小班分不清照片属哪块。
4. **存储位置**：`Pictures/{目录}/{文件名}.jpg`。Android 10+ 走 MediaStore（自有媒体免存储权限、相册立即可见、多级目录自动创建）；`< 29` 回落应用外部私有目录。
5. **拍照入口**：App 内 `AppPermissions.takePhoto` → `ACTION_IMAGE_CAPTURE`（只给相机）；浏览器/旧包回退 `input[capture=environment]`，两者都不提供相册入口。
6. **压缩与元信息**（对齐 supervision + 本仓库 v1.3 既有实现）：EXIF 读拍摄时刻与经纬度 → Canvas 压缩到参数「压缩最长边/质量」并画水印 → `keepExif` 把原片 EXIF 回写进成品（Orientation 归一、尺寸标签删除、MakerNote 删除）→ 存相册的那份即带机器可读的时间与坐标。

## 4. 代码修改（文件 + 要点）

- `param_parser.py`：`WATERMARKS` 扩为四项；新增 `TEMPLATE_VARS`/`TEXT_LIMITS`；`KEYS` 增 4 个 key；新增 `_text_param`、`_template_param`（占位符配对、未知变量、文件名禁 `/`、目录禁绝对路径与 `..`）；`default_params()` 改为从 `KEYS` 派生（新增 key 不会漏默认值）。
- `data/程序参数模板.xlsx`、`tpl/中幼林抚育林木采伐调查设计总表.xlsx`：重写「程序参数」sheet 共 10 个 key（含 说明/示例/默认值），行序：功能 → 项目名称 → 说明 → 目录 → 相片文件名 → 水印内容 → 压缩最长边 → 压缩质量 → 不显示列 → 轨迹采样间隔。
- `static/photo_tpl.js`（新增）：`context / render / sanitizeSeg / albumSubdir / photoName / watermarkLines`，纯逻辑、浏览器与 node 通用；App 名兜底只在这里出现一处。
- `static/app.js`：`renderPhotos` 改为本机拍摄记录（localStorage `forest_shots_plot_{id}`，最多 100 条）；`compressPhoto(file, ctx, coords)` 改用 `PhotoTpl.watermarkLines`；新增 `isNativeApp / nativePlugin / nativeCapture / startPhoto`；`handlePhoto` 删除上传分支，改为 `savePhoto` 写相册（浏览器回退下载）；旧包缺插件时明确提示升级，不静默退回已下线的上传路径。
- `templates/index.html`：按钮文案「拍摄 / 选择照片」→「拍照」；`photoList` 改用 `.shot-list`；引入 `photo_tpl.js`。
- `static/style.css`：新增 `.shot-list / .shot-item`。
- `android/.../AppPermissionsPlugin.java`（新增）：`takePhoto`（权限门 → FileProvider cache 文件 → `cameraResult`）、`readPhoto`（缓存内文件转 base64）、`savePhoto`（MediaStore 多级目录 + 真实路径回传）、`removeCacheFile`、`check/request/openSettings`。
- `android/.../MainActivity.java`：`registerPlugin(AppPermissionsPlugin.class)`（必须在 `super.onCreate` 前）。
- `android/app/src/main/AndroidManifest.xml`：删 `READ_MEDIA_IMAGES`（不再读相册），补 `<queries>` IMAGE_CAPTURE 可见性。
- `android/app/build.gradle`：versionCode 2 / versionName 1.1。
- `app.py`：`ASSET_VERSION = v1.5.0`。

## 7. 部署记录

- 网页部分：`bash deploy.sh` 同步 `app.py` / `param_parser.py` / `static/` / `templates/`，`kill -HUP` 重载 gateway；`ASSET_VERSION` 已升 `v1.5.0`，旧缓存 JS 不会再打已下线路径。
- APK：需新出 `versionCode 2 / versionName 1.1` 包（推 `android/**` 或 `v*` tag）。**旧包没有 AppPermissions 插件，拍照会明确提示升级**——上线顺序必须「先出 APK、再发网页」，否则调查员当天拍不了照。
- 存量项目不需要重传：无参数表时按默认模板生成目录与文件名；需要固定项目名时，把「项目名称」填进总表的「程序参数」sheet 后重新上传（覆盖保留调查数据）。
