# 011 - v1.5.1 迭代记录_相机返回丢结果补存

## 1. 需求背景（用户原话）

> app 里面 点击拍照，没有看到保存的位置有相片，已经授权，手机华为鸿蒙4.2？

现场追问三答：

1. 点「拍照」后相机**打开了、能拍**；
2. 拍完**直接闪回 App**，照片卡片下的状态文字**什么都没有**；
3. 装的是**昨天下午的 v1.1** 签名包。

## 2. 验证结果（改前现场）

- 线上网页确认为 v1.5（`/exp-survey/static/photo_tpl.js` 200，`app.js` 含 `PhotoTpl`/`AppPermissions`，按钮文案「拍照」），排除「旧网页」；
- 安装包 `apk/20261123_1726_抚育调查_v1.1_release.apk` 解包后 `classes.dex` 含 `AppPermissionsPlugin`/`takePhoto`/`savePhoto`，排除「旧包没插件」；
- 症状组合唯一指向：**相机 Activity 把承载页面的 WebView 一起回收了**。鸿蒙/EMUI 内存紧张时常发生：拍完返回时页面是全新加载的，`takePhoto` 的 Promise 随旧页面消失，`cameraResult` 回调里的 `PluginCall` 为 `null`，原片只躺在 App 缓存目录里 —— 相册当然没有，状态栏也回到空白。
- v1.1 的两处硬伤：① 启动相机前不落盘路径，插件实例被回收后无迹可寻；② `cameraResult` 只看 `RESULT_OK` 且失败时**删除原片**，而华为部分机型写盘成功后仍回 `RESULT_CANCELED`。

## 3. 设计方案（逻辑 + 口径依据）

对齐 hqz-supervision 处理「相机返回丢上下文」的做法（`doc/017` 的 `markReturnContext` / `getLastVideo`）：

1. **原生侧先落盘**：`launchCamera` 在 `startActivityForResult` **之前**把原片绝对路径与时间戳写进 `SharedPreferences`（`exp_photo_pending`），插件实例被回收也不丢。
2. **判据改成「文件真的有内容」**：`cameraResult` 里 `hasPhoto = 文件存在且长度>0`；`RESULT_CANCELED` 但有图 → 当成功返回；`RESULT_OK` 但没图 → 报「相机没有生成照片」；**不再删原片**。
3. **新增两个原生方法**：`getLastPhoto({consume})`（15 分钟内、文件有效的待补存原片，可选清标记）、`clearLastPhoto()`（正常流程存相册后清标记）。
4. **页面侧补存**：点「拍照」前把 `{subId, plotId, at}` 写进 `localStorage`（`forest_pending_capture`）。回到前台 / 重新进 App 时先问 `getLastPhoto`：拿到原片 → 恢复 `#/sub/<subId>/<plotId>` 路由 → `waitForDetail` 等详情加载 → 读原片 → 压缩+水印 → 存相册。
5. **两条入口、互不重复**：
   - 页面被重载（`captureBusy` 为 false）→ `resumePendingCapture`；
   - 页面没重载但回调丢失（`captureBusy` 为 true）→ 8 秒后 `adoptStuckCapture`，回前台每 5 秒重试一次。
   防重复靠两把锁：`captureSeq`（补存接管后旧 Promise 回来即作废）+ 「拿到原片立刻清 SharedPreferences 标记」（标记还在才说明这次 Promise 没回来）。

## 4. 代码修改（文件 + 要点）

- `android/.../AppPermissionsPlugin.java`：新增 `PREFS/KEY_PENDING_PATH/KEY_PENDING_AT/RECOVER_WINDOW_MS` 常量；`launchCamera` 启动相机前写标记；`cameraResult` 改为以文件内容判定、失败不再删原片、`call==null` 时保留标记；新增 `getLastPhoto`、`clearLastPhoto`、`pendingPathFromPrefs`、`clearPending`、`resultOf`。
- `static/app.js`：
  - 新增 `PENDING_CAPTURE_KEY` / `captureBusy` / `captureSeq` / `captureStartedAt` / `state.recoverTimer`；
  - `photoFromPath(path, plugin)`：`convertFileSrc` 拿到的若不是图片（跨源可能返回 HTML）就退回 `readPhoto` 的 base64；
  - `lastNativePhoto` / `clearNativeMarker` / `withTimeout`；
  - `nativeCapture` 加 150 秒超时，超时或 reject 时先尝试 `getLastPhoto`（华为 CANCELED 但有图），拿到原片**先清标记再读文件**；
  - `startPhoto` 记录待补存上下文 + 用 `captureSeq` 判定结果是否已被接管；
  - 新增 `resumePendingCapture` / `adoptStuckCapture` / `finishPendingShot` / `waitForDetail`；
  - `visibilitychange`（回前台）与 `bootstrap` 结束各触发一次补存探测。
- `app.py`：`ASSET_VERSION = v1.5.1`；`android/app/build.gradle`：versionCode 3 / versionName 1.2。

## 6. 反转记录

- 反转 v1.5「拿不到 `RESULT_OK` 就删原片」：改为以文件是否有内容为准，取消也不删（宁留垃圾，不误删照片）。
- 反转 v1.5「只靠 Promise 传递拍照结果」：结果必须有落盘旁路，页面重载后能自取。
- 保留：C20 的相册命名/目录口径、EXIF 回写、参数模板校验、无「从相册选择」。

## 7. 部署记录

- 网页：`bash deploy.sh`（`app.js` 带 `?v=v1.5.1`，旧缓存不再命中）。
- APK：需重出 **v1.2（versionCode 3）**；v1.1 没有 `getLastPhoto`，JS 会在检测不到该方法时直接放弃补存（`resumePendingCapture` 早退），不会报错但也不会补 —— **上线顺序仍是先出包、再发网页**。
- 复测清单（鸿蒙 4.2）：① 正常拍一张 → 相册 `Pictures/{项目名称}/{小班号}/` 有图；② 连续拍 5 张 → 相册 5 张、App 记录 5 条、无重名；③ 相机里取消 → 无图、无补存提示；④ 后台杀 App 再进 → 若上次留下未存原片会自动补一张。
